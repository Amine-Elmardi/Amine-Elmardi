MM-L2-009 · L2

Duplicate purchase order requires cancellation

Problem

A buyer accidentally creates a second order for the same requirement and asks to cancel or block the duplicate.

Error message / number

Not specified in the source.

Root cause

The source identifies a missed existing order or an absent duplicate check.

Affected modules

MM / FI

Transactions

ME22N, ME25, MIGO (122), MR8M, OMEt

Diagnosis / requirements

  1. Identify both orders and establish which is the duplicate
  2. Check whether goods receipts or invoices have already been posted

Solution

  1. For an unprocessed duplicate, the source describes setting deletion flags on all items in ME22N
  2. It also mentions ME25 as a blocking alternative, whose applicability requires confirmation
  3. If follow-on postings exist, coordinate the documented MIGO and MR8M correction references with FI before changing the order

Validation / configuration

Verify the duplicate is no longer open for processing. The source mentions OMEt as preventive configuration and MM_EINKBELEG for archiving. L2 reflects possible follow-on corrections.

Classification

L2: Functional analysis and coordinated correction.
